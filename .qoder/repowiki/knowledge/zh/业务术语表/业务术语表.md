### 问义树
- 定义：SemQuestTree 项目的核心数据结构与产品概念：将知识组织成一棵「判据树」（criteria tree），而非向量库或 embedding 索引。每个节点携带一个 yes 判据（事件级原子断言），叶子节点存放落位的内容；`add` 操作按自然语言逐层判定内容归属哪个叶子，`quest` 查询则沿相同路径检索，每次命中都附带完整的判定路径、P(yes) 概率与 token 消耗。
- 别名：criteria tree、判据树

### noul 模式
- 定义：问义树的题型方言之一：对每一层的所有真实判据发起一次批量 noul 问题，所有 P(yes) ≥ gate 的分支同时继续下探，形成多标签并行路由；最终得分 = 命中的叶子数量。根层之外的每层会自动生成 X_OTHER 兜底叶，该层无分支通过时即落入兜底。
- 别名：noul、多标签并发下行

### choice 模式
- 定义：问义树的另一种题型方言：每层只提一个问题，选项即子节点（描述即判据，默认取节点名）+ 显式的「以上都不符合」兜底选项；只要某一路径的累积概率低于 choiceGate（采纳线）即终止，最终得分 = 路径概率连乘，兜底或低于采纳线即视为无命中。
- 别名：choice、单选逐层下行

### 门控 (gate)
- 定义：控制问义树判定严格度的阈值参数：noul 模式下每层分支的 P(yes) 必须 ≥ noulGate 才继续下探；choice 模式下整条路径的概率连乘必须 ≥ choiceGate 才算命中。两个值均可在创建表时固定，也可在运行时的 UI 头栏调整，按表持久化。
- 别名：noulGate、choiceGate、gate

### respan 族模型
- 定义：一类免费模型（如 respan-*），在 Jev 后端中以 `{input,output}` 消息协议工作，且仅接受 noul 模式；用于 choice 表时会快速失败并返回明确错误，需切换到 jev 或 elephant 家族模型。
- 别名：respan-family models

### X_OTHER 兜底叶
- 定义：问义树每层自动生成的兜底分支，用于承接无法匹配任何真实判据的内容；该分支不参与决策请求（零次通过），当某层没有任何分支通过时即落入该层的 X_OTHER。删除某层最后一个真实分支时会移除空的兜底叶（含落位数据时拒绝删除）。
- 别名：fallback leaf、兜底叶

### 落位 (placement)
- 定义：`add` 操作的结果：一条内容经过问义树逐层判定后最终落入某个叶子节点的过程与结果。落位数据随表快照持久化到 `tables/<id>.json`，重启后可零模型回放。
- 别名：placed docs、落位数据

### 表 (table)
- 定义：问义树的项目内单位：一张表 = 一棵判据树，包含结构、判据、门控、落位与增长/编辑记录，持久化为 `tables/<id>.json`。表的创建时可固定 noul 或 choice 模式，之后不可更改。
- 别名：criteria table、树

### 驱动意图
- 定义：项目内置的演示用问义树（Driver Intents），用于展示司机相关场景（Fare/Cargo/Schedule/Service 等分支）的 add 落位与 quest 检索效果。英文 demo 通过 `SemQuestClient seed` 初始化，中文 demo 随 viz 服务启动自动迁移。
- 别名：driver intents、司机意图

### mock 后端
- 定义：内置的零凭据、零 token 决策后端，使用确定性关键词子串匹配（内容包含节点名 → P = 0.95），用于演示与测试。不是真正的判断逻辑，生产环境应切换至 jev/openrouter/bailian。
- 别名：mock backend、关键词匹配
